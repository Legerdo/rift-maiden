# RIFT MAIDEN
## Claude Opus 5.5 — 2D 픽셀아트 가로 사이드뷰 인크리멘탈 액션 슈터 원샷 제작 프롬프트

Windows 11 환경에서 사용 가능한 개발 도구를 활용하여 **TypeScript + Phaser 3 + Vite** 기반의 완성도 높은 2D 픽셀아트 게임을 실제 제작하라.

목표는 단순히 요구 기능이 동작하는 프로토타입이 아니다.

**약 64x64 크기의 서브컬처 미소녀 픽셀아트 캐릭터를 직접 조작하여 싸우고, 전투를 거듭하면서 무기·스킬·자동화·빌드가 폭발적으로 성장하는 가로 사이드뷰 인크리멘탈 액션 슈터**를 만든다.

구현뿐 아니라 실제 실행, 플레이 검증, 밸런스 조정, 화면과 조작감 검토, 결함 수정까지 이번 작업 범위에 포함한다.

---

# 1. 작업 방식

너는 이번 작업에서 다음 역할을 동시에 수행한다.

- 시니어 게임 디자이너
- 게임플레이 프로그래머
- 픽셀아트/테크니컬 아트 담당
- UI/UX 디자이너
- 게임필·쥬스 담당
- 밸런스 디자이너
- QA 및 플레이테스터

사용자에게 사소한 결정을 넘기지 마라.

명시되지 않은 세부사항은 다음 우선순위로 스스로 결정한다.

1. 실제 재미
2. 조작감과 전투 손맛
3. 플레이 가독성
4. 성장 체감
5. 완성도
6. 유지보수성
7. 콘텐츠 양

하나로 합리적으로 결정할 수 없는 중요한 문제가 실제 구현을 막는 경우에만 질문한다.

단순한 색상, 수치, 적 이름, 사소한 UI 위치 같은 것은 자율적으로 결정한다.

범위가 커질 경우 기능을 반쯤 만들지 말고 **콘텐츠 수를 줄여 완성도를 유지한다.**

# 2. 게임 핵심

게임 제목 기본값:

# RIFT MAIDEN
## 리프트 메이든

장르:

**2D 픽셀아트 / 가로 사이드뷰 / 액션 슈팅 / 인크리멘탈 성장 / 가벼운 로그라이트 빌드**

핵심 판타지:

> 처음에는 소형 화기로 적 몇 마리를 힘겹게 쓰러뜨리던 미소녀 주인공이 전투와 강화를 반복하면서, 총탄·관통탄·도탄·에너지 빔·드론·미사일·연쇄폭발·특수 스킬을 동시에 운용하는 압도적인 전투 병기로 성장한다.

단, 성장했다고 플레이어가 할 일이 없어지면 안 된다.

자동화는 반복 노동을 제거하고 더 높은 수준의 전투 판단을 남겨야 한다.

# 3. 최우선 게임 디자인 원칙

이 게임에서 가장 중요한 것은 다음 다섯 가지다.

### 1. 직접 조작하는 재미
움직이고, 조준하고, 쏘고, 피하는 것 자체가 재미있어야 한다.

### 2. 강한 전투 피드백
총알이 적에게 맞았다는 사실을 숫자가 아니라 화면과 소리만으로도 느낄 수 있어야 한다.

### 3. 눈에 보이는 성장
단순히 내부 DPS 숫자만 증가하면 안 된다.

성장하면서 실제로:

- 총알 수가 늘고
- 탄환 형태가 변하고
- 관통이 생기고
- 적이 연쇄 폭발하고
- 드론이 따라붙고
- 오라가 생기고
- 미사일이 날아가고
- 공격 범위가 변하고
- 새로운 스킬이 추가되는 등

플레이 화면 자체가 달라져야 한다.

### 4. 플레이 방식이 변하는 빌드
`공격력 +5%`만 반복하지 않는다.

업그레이드를 통해 실제 전략과 조작 방식이 달라져야 한다.

### 5. 짧지만 완결된 게임
큰 게임을 어설프게 만들기보다 작은 게임을 제대로 완성한다.

---

# 4. 플레이어 캐릭터

주인공은 **64x64 전후의 픽셀아트 미소녀 캐릭터**다.

정확히 모든 프레임이 64x64일 필요는 없지만, 게임 내에서 대략 이 정도의 존재감을 가진다.

서브컬처 계열 미소녀 디자인을 사용한다.

예를 들어:

- 차원 균열을 추적하는 건슬링어
- 사이버 마법소녀
- 테크노 위치
- 미래형 퇴마사
- 유물 사냥꾼
- 에너지 무기를 쓰는 용병

중 가장 게임에 잘 어울리는 방향을 선택한다.

복장은 지나치게 복잡하게 만들어 픽셀 가독성을 해치지 않는다.

실루엣만 보더라도:

- 머리 형태
- 주무기
- 몸 방향
- 행동 상태

가 읽혀야 한다.

최소한 다음 애니메이션 상태를 구현한다.

- Idle
- Move
- Aim / Shoot
- Hit
- Dash 또는 회피
- Skill
- Defeat

필요하다면:

- Landing
- Reload
- Empowered
- Victory

를 추가한다.

캐릭터가 그냥 사각형 몸통에 머리카락 몇 픽셀 붙인 임시 그래픽처럼 보이면 실패다.

# 5. 기본 조작

기본 권장 조작:

- A / D : 좌우 이동
- 마우스 : 조준
- 좌클릭 : 기본 사격
- Shift 또는 우클릭 : 대시 / 회피
- Q / E : 액티브 스킬
- Space : 점프가 게임에 실제로 필요할 경우 사용
- Esc : 일시정지

점프는 반드시 넣을 필요가 없다.

게임 흐름상 지상 이동 + 대시만 있는 편이 더 완성도가 높다면 점프를 제거해도 된다.

**필요 없는 기능을 장르 관습이라는 이유만으로 넣지 마라.**

# 6. 전투 기본 구조

화면은 가로 사이드뷰다.

주인공을 중심으로 적들이:

- 오른쪽에서 진입
- 좌우에서 협공
- 위에서 비행
- 후방에서 기습
- 특수 웨이브에서 다방향 공격

등 다양한 형태로 압박한다.

전투는 단순히 적 HP가 늘어나는 방식으로 어려워지지 않아야 한다.

적 유형에 따라 플레이어 대응법이 달라져야 한다.

예:

### 잡몹
빠르게 몰려오는 기본 적.

### 원거리 적
거리 유지가 필요하다.

### 돌진형
이동과 대시 타이밍을 요구한다.

### 비행형
조준 방향을 바꾸게 한다.

### 장갑형
정면 방어나 특정 약점을 가진다.

### 지원형
주변 적을 강화하거나 소환한다.

### 엘리트
기본 적의 규칙에 추가 능력이 붙는다.

### 보스
패턴, 약점, 페이즈 또는 환경 변화를 가진다.

---

# 7. 핵심 전투 사이클

기본 사이클:

**조준 → 사격 → 피격 확인 → 처치 → 자원 획득 → 강화 → 더 많은 적 → 더 강한 빌드 → 엘리트/보스**

이 루프가 빠르게 반복되어야 한다.

초반 몇 초 안에:

- 이동
- 사격
- 적 처치
- 자원 획득

을 모두 경험할 수 있어야 한다.

초반에 긴 설명부터 시작하지 않는다.

튜토리얼은 실제 플레이 속에서 짧게 알려준다.

---

# 8. 게임필 / Juice — 매우 중요

게임필은 마지막에 파티클 몇 개 얹는 작업이 아니다.

입력부터 결과까지 전체 체인에 적용한다.

## 사격

총을 쏠 때 최소한 다음 중 적절한 조합을 사용한다.

- muzzle flash
- 총기 또는 팔 recoil
- 짧은 총구 후광
- 탄피 배출
- 발사 사운드
- 미세한 카메라 반응
- 강한 무기의 경우 더 무거운 recoil
- 빔이나 특수무기의 distinct한 충전/방출 연출

모든 무기가 같은 피드백을 사용하면 안 된다.

무기에 따라:

- 연사형은 리듬
- 샷건은 충격량
- 레일건은 순간 정지와 관통
- 빔은 지속적인 에너지
- 미사일은 추적과 폭발

처럼 다른 손맛을 준다.

---

# 9. 피격 피드백

적을 맞힐 때:

- hit flash
- impact spark
- 작은 파편
- 적절한 knockback
- 피격 사운드
- 데미지 숫자
- 강한 공격의 micro hit-stop

등을 조합한다.

전부 매 타격마다 최대 강도로 사용하지 않는다.

공격 위력에 따라 강도가 달라져야 한다.

예:

기본탄:
작은 스파크 + 짧은 플래시

치명타:
더 큰 스파크 + 강조 숫자 + 다른 사운드

샷건:
큰 반동 + 넓은 파편

레일건:
짧은 hit-stop + 관통선 + 강한 충격

보스 약점 파괴:
카메라 반응 + 큰 파편 + 화면 강조

---

# 10. 적 처치 피드백

적이 HP 0이 되어 그냥 사라지는 방식은 피한다.

가능한 범위에서:

피격  
→ 경직  
→ 마지막 공격 반응  
→ 파괴 또는 쓰러짐  
→ 파편/에너지 방출  
→ 자원 드롭  
→ 자원이 플레이어에게 흡수

같은 흐름을 만든다.

강한 적은 사망 연출도 더 강하게 만든다.

---

# 11. 카메라

카메라는 전투를 돕는 용도다.

사용 가능:

- 짧은 camera shake
- 강한 공격 순간 작은 impulse
- 보스 등장 시 framing
- 엘리트 처치 시 약한 강조
- 특수 스킬 순간 zoom 또는 kick

금지:

- 모든 총알마다 큰 흔들림
- 계속 확대/축소
- 멀미를 유발하는 흔들림
- 캐릭터 위치 확인을 방해하는 연출

설정에서 screenshake 강도를 낮추거나 끌 수 있게 하는 것을 권장한다.

---

# 12. 이동감

주인공 이동은 즉각적이면서도 생명력이 있어야 한다.

고려할 요소:

- responsive acceleration
- 빠른 방향 전환
- 애니메이션 상태 전환
- 대시 잔상
- 착지 반응
- 작은 먼지/지면 파티클
- 대시 쿨다운 시각화

입력 지연처럼 느껴지는 과도한 acceleration은 피한다.

# 13. 인크리멘탈 구조

이 게임의 핵심이다.

성장은 세 단계 이상으로 나눈다.

## A. 순간 성장

수 초 단위 보상.

예:

- 자원 획득
- 콤보 증가
- 짧은 버프
- 특수 탄약
- 치명타 연쇄
- 자석 효과

## B. 런 내부 성장

한 번의 플레이 동안 선택하는 강화.

예:

- 새로운 발사 형태
- 탄환 증가
- 관통
- 도탄
- 폭발
- 드론
- 실드
- 특수 스킬
- 원소 효과
- 강화된 대시

## C. 영구 성장

런이 끝난 뒤 남는 성장.

예:

- 새로운 무기 계열
- 새로운 업그레이드 풀
- 추가 스킬
- 시작 장비
- 새로운 지역
- 새로운 적/보스
- 자동화 시스템
- 새로운 빌드 archetype

# 14. 숫자만 커지는 업그레이드를 피한다

다음 같은 업그레이드는 보조적으로만 사용한다.

- 공격력 +5%
- 체력 +3%
- 이동속도 +2%

이런 업그레이드만 수십 개 넣지 않는다.

더 좋은 업그레이드:

- 탄환이 적을 관통한다.
- 관통 후 탄환이 두 개로 갈라진다.
- 치명타 적중 시 주변 적으로 번개가 전이된다.
- 마지막 탄환이 폭발한다.
- 대시 중 무적이 생긴다.
- 대시 종료 시 유도탄을 발사한다.
- 적 처치 시 일정 확률로 지원 드론이 생성된다.
- 샷건 탄환이 벽에 튕긴다.
- 과열 상태에서 공격력이 크게 증가하지만 이동 속도가 감소한다.

**수치 변화보다 규칙 변화가 우선이다.**

# 16. 빌드 시너지

업그레이드는 서로 독립적으로 존재하지 않아야 한다.

예:

**Crit + Chain Lightning**

치명타 발생  
→ 번개 전이  
→ 전이된 적 처치  
→ 추가 콤보  
→ 공격속도 상승

또는:

**Pierce + Split Shot**

관통 성공  
→ 탄환 분열  
→ 여러 적 적중

또는:

**Drone + On Kill**

적 처치  
→ 드론 공격속도 증가  
→ 더 많은 처치  
→ 일정 시간 폭주 상태

플레이어가:

> 아 이거랑 이거 같이 먹으면 미친 빌드 되겠는데?

라고 생각할 수 있어야 한다.

# 17. 자동화 철학

자동화는 플레이를 제거하지 않는다.

초반:

플레이어가 대부분 직접 처리한다.

중반:

드론, 유도탄, 자동 회수 등이 반복 행동을 줄인다.

후반:

자동 시스템은 잡몹을 처리하고 플레이어는:

- 위험한 적 우선 제거
- 보스 약점
- 스킬 타이밍
- 위치 선정
- 콤보 유지
- 빌드 운영

같은 고차원 행동에 집중한다.

좋은 자동화:

> 예전에 직접 하던 귀찮은 일을 시스템이 대신한다.

나쁜 자동화:

> 아무것도 안 해도 모든 전투가 끝난다.

---

# 18. 실력과 성장의 연결

액티브 플레이를 잘하면 성장 속도가 빨라진다.

예:

### 약점 사격
추가 자원.

### 연속 처치
자원 multiplier.

### 노히트
보너스 게이지.

### 위험 거리 전투
추가 보상.

### 정확한 회피
일시적인 공격 보너스.

### 엘리트 빠른 처치
추가 강화 선택권.

하지만 액션 게임 숙련도가 낮다고 아예 진행하지 못해서는 안 된다.

영구 성장과 자동화가 보완한다.

---

# 19. 자원 획득 연출

적이 죽으면:

- 에너지 조각
- 코어
- 크레딧
- 차원 파편

등 테마에 맞는 자원이 물리적으로 튀어나오게 한다.

자원은:

튀어나옴  
→ 잠깐 떠있음  
→ 플레이어 근접 시 빨려옴  
→ UI에 들어감

의 흐름을 가진다.

강화된 자석 능력을 얻으면 흡수 범위와 연출이 눈에 띄게 변한다.

자원 획득은 단순 숫자 +1보다 시각적으로 만족스러워야 한다.

---

# 20. 적 구성

권장 최소 구성:

- 기본 근접 적
- 빠른 돌진 적
- 원거리 적
- 비행 적
- 장갑 적
- 특수 지원 적
- 엘리트 변종
- 보스

약 6~10종 정도로 충분하다.

적 30종을 대충 만드는 것보다 8종의 행동이 확실히 다른 편이 낫다.

---

# 21. 보스

최소 1개의 제대로 된 보스를 만든다.

가능하면 2~3개.

보스는 큰 HP만 가진 적이면 안 된다.

포함할 수 있는 요소:

- 공격 페이즈
- 약점
- 위치 이동
- 패턴 변화
- 소환
- 방어 파괴
- 환경 공격
- stagger
- enrage

첫 보스는 플레이어가 지금까지 배운:

- 이동
- 대시
- 조준
- 우선순위
- 빌드

를 자연스럽게 시험해야 한다.

---

# 22. 스테이지

2~4개 정도의 짧지만 특징적인 지역을 권장한다.

예:

### 네온 폐허
기본 전투를 배우는 지역.

### 붕괴된 연구단지
비행형과 원거리 적 증가.

### 차원 오염지대
환경 효과와 특수 적 등장.

### 균열 중심부
엘리트와 최종 보스.

정확한 테마는 더 좋은 아이디어가 있다면 변경해도 된다.

Biome은 단순 배경 교체로 끝내지 않는다.

적 구성이나 전투 리듬에 차이를 준다.

---

# 23. 픽셀아트 방향

픽셀아트의 핵심은 디테일 양이 아니라 가독성이다.

### 캐릭터
약 64x64.

### 일반 적
대략 24x24 ~ 64x64.

### 대형 적/보스
그 이상 가능.

권장:

- 명확한 실루엣
- 제한적이지만 풍부한 팔레트
- 명암 단계 명확화
- 배경 대비 확보
- 공격 이펙트와 캐릭터 색상 분리
- 불필요한 서브픽셀 표현 금지

픽셀아트인데 고해상도 브러시 그림을 축소한 것처럼 보이면 안 된다.

---

# 24. 애니메이션 원칙

프레임 수를 무조건 늘리지 않는다.

적은 프레임이라도:

- anticipation
- impact
- recovery
- secondary motion

을 활용한다.

예:

사격:

준비  
→ 발사  
→ recoil  
→ 복귀

대시:

몸 기울기  
→ 이동  
→ 잔상  
→ 복귀

피격:

flash  
→ knockback  
→ recovery

프레임 수보다 포즈가 중요하다.

---

# 25. VFX 원칙

픽셀 스타일을 유지한다.

사용 가능:

- pixel sparks
- small debris
- muzzle flash
- impact ring
- pixel smoke
- shockwave
- afterimage
- energy trail
- glow 계열의 제한적인 후처리

지나친 blur나 현대적 고해상도 파티클로 픽셀 스타일을 깨지 않는다.

---

# 26. 화면 혼잡 관리

후반에는 공격이 많아질 수 있다.

따라서 다음 우선순위를 유지한다.

1. 플레이어 위치
2. 위험한 적 공격
3. 보스 패턴
4. 플레이어 공격
5. 자원
6. 장식 VFX

적 공격은 플레이어 공격보다 읽기 쉬워야 한다.

피해를 주는 오브젝트와 장식 파티클을 혼동하게 만들지 않는다.

데미지 숫자가 화면을 전부 가리지 않게 한다.

---

# 27. 콤보 / Flow

가능하다면 전투 흐름을 강화하는 간단한 콤보 시스템을 도입한다.

예:

빠른 연속 처치  
→ Combo 증가  
→ 자원 multiplier  
→ 일정 단계마다 VFX 강화

하지만 콤보를 유지하기 위해 의미 없는 잡몹 한 마리를 찾느라 스트레스받게 만들지 않는다.

콤보는 보상이지 족쇄가 아니다.

---

# 28. 런 길이

권장:

약 8~20분.

최초 의미 있는 전체 진행:

약 15~30분 안에 경험할 수 있게 한다.

초반부터 지나치게 느린 idle 게임처럼 만들지 않는다.

첫 몇 분 동안 반드시 여러 번의:

- 강화
- 새로운 공격
- 새로운 적
- 눈에 보이는 파워 증가

를 경험시킨다.

---

# 29. 메타 성장

런 종료 후 영구 자원을 제공한다.

예:

`균열 파편`

사용 가능 항목:

- 새로운 무기
- 새로운 스킬
- 새로운 업그레이드
- 시작 장비
- 신규 드론
- 신규 지역
- 특별한 빌드 규칙

Flat stat은 일부 허용하지만 중심이 되어서는 안 된다.

---

# 30. Prestige

Prestige는 필요한 경우에만 넣는다.

넣는다면 너무 자주 리셋시키지 않는다.

좋은 Prestige는:

새로운 시스템  
새로운 빌드  
새로운 자동화  
새로운 지역  
새로운 난이도 변형

을 열어야 한다.

나쁜 Prestige:

> 모든 걸 초기화합니다. 대신 공격력 +12%.

이런 구조는 피한다.

---

# 31. 난이도 곡선

플레이어 경험은 대략 다음처럼 흘러간다.

초반:
약하지만 충분히 싸울 수 있음.

중반:
빌드가 조립되기 시작함.

후반:
강한 시너지로 화면을 장악함.

보스:
강해진 빌드가 실제로 시험받음.

플레이어가 성장했는데 적 HP도 정확히 같은 비율로 증가해 아무 변화가 없는 식의 scaling은 피한다.

**성장하면 실제로 강해졌다는 느낌을 줘라.**

---

# 32. 게임 오버

사망은 진행을 완전히 끊는 처벌보다 다음 플레이로 연결되어야 한다.

결과 화면에:

- 생존 시간
- 처치 수
- 보스
- 최고 콤보
- 획득 자원
- 사용한 빌드
- 신규 해금

등을 보여준다.

다시 시작 버튼은 즉시 찾을 수 있게 한다.

긴 로딩이나 메뉴 왕복을 강요하지 않는다.

# 33. UI

픽셀아트 스타일과 통일한다.

HUD에는 필요한 정보만 표시한다.

예:

- HP / Shield
- Skill cooldown
- 현재 무기
- 경험치/성장 게이지
- 핵심 자원
- Combo

모든 수치를 항상 화면에 표시하지 않는다.

인크리멘탈 게임이라고 UI가 엑셀 시트가 되어서는 안 된다.

# 34. 업그레이드 선택 UI

업그레이드가 등장했을 때:

- 이름
- 간단한 아이콘
- 짧은 설명

좋음.

반대로:

같은 개발자 문구는 플레이어 UI에 쓰지 않는다.

# 42. 저장

영구 성장 시스템이 있으므로 저장 기능을 구현한다.

웹 환경에서는 적합한 로컬 저장 방식을 사용한다.

저장 대상 예:

- 메타 자원
- 해금
- 설정
- 진행 기록

잘못된 저장 데이터로 게임 전체가 실행 불가능해지지 않게 최소한의 방어 처리를 한다.

필요하다면 저장 초기화 기능도 제공한다.

# 43. 화면 해상도

픽셀아트 특성에 맞는 논리 해상도를 사용한다.

권장 범위:

- 320x180
- 384x216
- 480x270

중 프로젝트에 가장 적합한 것을 선택한다.

정수 배율과 nearest-neighbor scaling을 우선한다.

픽셀이 흐릿해지지 않게 한다.

다양한 화면 비율에서 심하게 깨지지 않게 처리한다.

---

# 44. 배경

단색 또는 빈 화면으로 끝내지 않는다.

2D 사이드뷰에 적합한 다층 배경을 만든다.

예:

- 먼 배경
- 중간 구조물
- 플레이 필드
- foreground decoration

parallax를 적절히 사용한다.

하지만 배경이 전투 가독성을 방해하지 않아야 한다.

---

# 45. 게임 세계와 최소한의 목적

복잡한 스토리가 필요하지는 않다.

하지만 플레이어가 왜 싸우는지는 알아야 한다.

예:

차원 균열이 도시를 침식하고 있으며 주인공은 균열의 중심부까지 진입해 원인을 파괴해야 한다.

스토리는 짧게 유지한다.

긴 텍스트보다:

- 지역 변화
- 적 변화
- 보스
- 간단한 메시지

를 통해 보여준다.

# 47. 게임필 검증 기준

구현 후 실제 플레이하면서 다음 질문에 답한다.

### 이동
- 입력 즉시 반응하는가?
- 방향 전환이 답답하지 않은가?
- 대시가 유용하고 시각적으로 명확한가?

### 사격
- 총을 쏘는 것 자체가 재미있는가?
- 총기별 차이가 손으로 느껴지는가?
- 탄환이 적에게 맞았다는 느낌이 있는가?

### 적
- HP 덩어리처럼 느껴지지 않는가?
- 각 유형의 행동이 구분되는가?

### 성장
- 업그레이드를 선택했을 때 즉시 변화가 느껴지는가?
- 후반 화면이 초반과 확연히 다른가?

### 인크리멘탈
- 반복 행동이 점차 자동화되는가?
- 자동화 후 새로운 판단거리가 생기는가?

### 가독성
- 화려해져도 캐릭터와 위험 요소가 보이는가?

### 재미
- 다시 한 판 하고 싶은 이유가 실제로 존재하는가?

문제가 있다면 직접 수정한다.

# 48. 피해야 할 실패 패턴

다음 상태에서는 완성으로 간주하지 않는다.

- 기능은 있지만 손맛이 없음
- 이동이 뻣뻣함
- 사격이 레이캐스트/탄환 생성만 하고 끝남
- 적이 그냥 다가와서 HP만 깎임
- 모든 적 행동이 동일함
- 업그레이드 대부분이 단순 퍼센트 증가
- 성장했는데 화면 변화가 없음
- 자동 공격을 얻은 뒤 플레이할 이유가 사라짐
- 적과 플레이어 탄환 구분이 안 됨
- 파티클 때문에 화면이 안 보임
- 미소녀 주인공의 존재감이 없음
- 배경이 테스트용 격자/단색임
- UI가 개발자 디버그 화면 같음
- 죽으면 모든 게 의미 없이 초기화됨
- 튜토리얼이 긴 설명창으로 시작함
- 구현은 되어 있지만 실제로 플레이하면 프로토타입 느낌이 남음

# 최종 실행 지시

이제 계획 문서만 작성하지 말고 실제 게임을 제작하라.

먼저 현재 작업 환경과 프로젝트 상태를 확인한다.

프로젝트가 없다면 적절하게 생성한다.

그다음 핵심 플레이 루프부터 구현하고 실제 실행한다.

게임의 첫 번째 목표는:

> 미소녀 캐릭터를 움직이고, 적을 조준해 총을 쐈을 때 그 순간부터 재미있게 느껴지는 것.

이다.

이게 확보되지 않은 상태에서 메타 시스템부터 잔뜩 만들지 않는다.

첫 전투가 재미있어지면:

전투  
→ 강화  
→ 빌드  
→ 자동화  
→ 보스  
→ 결과  
→ 영구 성장  
→ 재도전

순으로 전체 게임을 연결한다.

각 단계에서 직접 실행하고 검증한다.

구현 도중 원래 설계보다 더 좋은 아이디어가 발견되면 핵심 정체성을 유지하는 범위에서 자율적으로 적용한다.

단순한 요구사항 충족 게임이 아니라,

**플레이어가 처음에는 직접 총 한 자루를 쏘다가 몇 분 뒤에는 탄환·빔·드론·미사일·연쇄효과가 서로 맞물려 화면 전체를 장악하고, 그 성장이 다시 다음 플레이를 유도하는 고품질 픽셀아트 인크리멘탈 액션 슈터**

를 목표로 한다.

코드 작성만 하고 성공했다고 선언하지 마라.

실제로 실행하고 플레이하고 수정하라.

최종적으로 Windows 11 환경에서 설치 → 실행 → 플레이 → 성장 → 보스 → 사망 또는 클리어 → 영구 성장 → 재도전까지의 전체 루프가 실제로 동작하는 상태로 마무리하라.
